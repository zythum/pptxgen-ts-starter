# Workflow 07 — QA and Delivery Gate

## Contract

**Inputs:** generated deck, `.deck/`, slide comments, tokens, and assets.
**Output:** P0/P1-clean deck with a completed structured layout audit, any
constrained repairs, and a full second pass.
**Gate:** do not deliver with any open P0 or P1 issue.
**Checklist:** `references/qa/checklist.md`.
**Validation:** static checks, type/lint/generate, geometry and cross-slide
layout audit, viewer inspection, and target PowerPoint review when available.
**Resume:** rerun the full checklist after any content/layout/token/asset change.

Stage 07 strengthens the existing seven-stage workflow; it is not an eighth
stage and does not create another `.deck/` planning file. A repair that changes
an approved decision must return to the applicable earlier Gate.

## Severity

| Level | Meaning                                              | Required action                      |
| ----- | ---------------------------------------------------- | ------------------------------------ |
| P0    | Broken, false, missing, overflowed, or unopenable    | Fix immediately                      |
| P1    | Visible correctness/accessibility/consistency defect | Fix before delivery                  |
| P2    | Suboptimal but usable                                | Fix when cheap; document if retained |
| P3    | Taste/optional polish                                | Avoid churn                          |

## 1. Run the canonical checklist

Use every section in `references/qa/checklist.md`. Important truth sources:

- external facts resolve to `.deck/research.md` `F-N` cards;
- supplied facts resolve to `user-material:<id>`;
- pages/roles/messages come from `.deck/outline.md`;
- layout/visual/token decisions come from `.deck/spec.md`;
- runtime values come from `src/token/`;
- implementation intent is summarized in slide comments.

## 2. Static and build checks

Adapt paths only when the project structure differs:

```bash
# Placeholder content
rg -n "TODO|TBD|Lorem|XXX|undefined" src/ .deck/

# Bare 6-digit hex in slide/component source (token files are excluded)
rg -n '["'"'][0-9A-Fa-f]{6}["'"']' src/slides/ src/components/

# Obvious literal type values; review controlled exceptions manually
rg -n 'fontSize: [0-9]|fontSize=\{[0-9]|fontFace: ["'"']' \
  src/slides/ src/components/

# Broken asset paths and traceability are checked against spec/comments
npm run typecheck
npm run lint
npm run generate
```

A grep hit is evidence to inspect, not always proof of a defect. A controlled
literal exception must carry its measurement/rationale comment.

## 3. Measurement checks

For each variable-length text block, use the actual font, width, margin, and
leading. Re-measure after edits.

```bash
npx tsx scripts/estimate-text.ts -w 5.7 -f "16pt Inter" \
  --leading 24 --json "Actual slide text"
```

For every raster image, inspect metadata and compare native ratio with its slot:

```bash
npx tsx scripts/image-tool.ts --image src/media/images/photo.png
```

For required text/background pairs:

```bash
npx tsx scripts/color-tool.ts --hex 1F2937 --hex FAFAFA --contrast --json
```

## 4. Cross-file consistency

Verify manually or with project tooling:

- outline page count = spec mapping count = slide file/composition count;
- slide numbers are continuous and unique;
- every canonical comment field exists and matches outline/spec;
- every `F-N`, user-material, layout, variant, and asset ID resolves;
- spec §3/§4 values equal runtime tokens;
- all local asset paths exist;
- speaker notes have Hook/Track/Action/Transition and no placeholders.

## 5. Structured layout audit

Audit from both source geometry and the generated rendering. A screenshot alone
cannot prove exact geometry, and source boxes alone cannot reveal every visual
occlusion or font-rendering issue. Resolve child coordinates through nested
`Group` offsets before comparing absolute boxes.

For every candidate issue, record a concise structured entry in the working QA
report or agent state; do not add a fifth `.deck/` planning file:

```text
QA-L-001 | P1 | slide 04 | unintended-overlap | title,chart
expected: title bottom + approved gap <= chart top
observed: overlap 0.12in | authority: layout L10 | status: open
```

### 5.1 Intra-slide collision and boundary audit

For each positioned element, identify semantic role, type, absolute
`x/y/w/h`, parent/group, layer, and whether overlap is intentional. Verify:

- every box stays inside the approved canvas and safe-area exceptions are
  intentional;
- measured text plus margins fits its text box;
- visible elements do not unintentionally overlap, cover, clip, or hide one
  another;
- card gaps, padding, baselines, and repeated-item geometry are coherent;
- after content composition, whitespace around primary content feels intentional,
  supports hierarchy, and has not been filled automatically with decoration;
- raster assets match their locked slot ratio;
- bottom anchors do not collide with related body content:
  `max(body.y + body.h) + gap <= anchor.y`, and
  `anchor.y + anchor.h <= canvasHeight - safeBottom`.

An intersection is a candidate, not automatically a defect. Exclude or classify
before repair:

- full-canvas backgrounds and low-contrast decorative layers;
- a container against its own children;
- connectors, callouts, masks, highlights, and other documented layering;
- the anchor itself when checking the body-to-anchor relation;
- unrelated body elements outside the anchor's horizontal range or footer band.

Still inspect excluded pairs in the rendering: an intended overlap becomes a
defect when it hides required information or breaks legibility.

### 5.2 Cross-slide anchor consistency audit

Compare only comparable cohorts: pages sharing a core layout or registered
variant, plus recurring elements with the same semantic role. Do not normalize
page-specific content merely because two boxes look similar.

Use this authority order for expected geometry:

1. approved spec §7/§8 and the referenced core layout;
2. a shared component's fixed geometry;
3. a conforming representative page when neither source fixes the value.

Compare titles, content tops, margins, page numbers, footers/sources, recurring
accents, card geometry, and repeated visual slots. After content composition,
also review recurring major margins and gaps as visual rhythm, without
normalizing intentionally sparse pages. Shared-component and spec-locked
coordinates should match exactly. Otherwise, drift over `0.05in` is a review
trigger, not automatic proof of error; accept intentional variance only when
the layout/variant or page role explains it.

## 6. Constrained LLM repair loop

The repairer receives the structured issue entries, affected renderings, source
geometry, `.deck/` authorities, and slide comments. It fixes the narrowest
verified cause and must preserve the stage 05/06 locks unless the workflow is
explicitly reopened.

### 6.1 Allowed without reopening an earlier Gate

- restore an element to geometry already defined by its core layout, registered
  variant, or shared component;
- adjust page-local `x/y/w/h`, gap, padding, or text-box dimensions within the
  same approved layout and visual slot;
- use an already approved typography role when measurement proves it necessary;
- crop or resize the same approved raster asset to its already locked slot;
- apply the same proven correction to directly comparable pages.

These repairs must not change the core message, factual values, source meaning,
visual provenance, or speaker-note intent. Apply mutations serially per file,
then regenerate before accepting the fix.

### 6.2 Forbidden automatic changes and escalation

The QA repairer must not silently:

- invent or switch a layout, or create unregistered geometry;
- change visual type, source, provenance, asset, or slot ratio;
- rewrite content, alter data, add/remove pages, or change the outline role;
- invent colors, change palette/font tokens, or introduce magic values;
- waive an applicable Gate because a local repair is inconvenient.

Escalate through the existing workflow:

| Required change                                      | Return path                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------- |
| Visual type/source/asset/slot decision               | rerun 06 preflight, then 05; update spec §7/comment as needed |
| New layout, variant, or global anchor rule           | reopen stage 04 Gate; register spec §8; then rerun 06 → 05    |
| Token, palette, font, or global design-system change | reopen stage 04 Gate and synchronize runtime tokens           |
| Core message, role, page split, or page count        | reopen stage 03 Gate, then all affected downstream stages     |

A delegated Gate may remain delegated only within the scope already recorded in
`.deck/brief.md`; silence during QA is not new delegation.

### 6.3 Repair verification

For each repair batch:

1. update the affected source and canonical comment if its recorded intent
   legitimately changed through an approved return path;
2. re-measure affected text/images and rerun type/lint/generate as applicable;
3. rerun the affected single-slide audit;
4. rerun cross-slide comparison for its cohort;
5. inspect the regenerated rendering and mark the issue fixed only when the
   evidence clears it.

If the smallest allowed repair cannot clear the issue, stop local iteration and
escalate; do not accumulate arbitrary nudges that drift from the approved
layout.

## 7. Full visual review

Open the generated deck in the browser viewer and inspect every page in order.
Then, when possible, open it in the target PowerPoint environment to check font
fallback, tables, chart labels, notes, and media.

Review:

- overflow, overlap, clipping, stretching, and harmful occlusion;
- title/margin/anchor alignment across page flips;
- density target from spec rather than a universal quota;
- contrast and projector/back-row legibility;
- cover/closing echo and chapter transitions;
- whether each visual is necessary and correctly credited.

## 8. Fix with the right lever

| Problem          | First action                            | Escalation when the lock must change          |
| ---------------- | --------------------------------------- | --------------------------------------------- |
| Text overflow    | enlarge/reflow within approved geometry | approved type role; reopen 03 if text changes |
| Image distortion | crop/resize to locked slot              | rerun 06 for a different slot ratio           |
| Overlap          | adjust measured local geometry          | choose/register a better layout               |
| Crowding         | restore approved spacing and bounds     | reopen 03 to remove or split content          |
| Inconsistency    | restore authoritative anchor            | approve a global layout-rule change           |
| Weak contrast    | use an allowed palette pairing          | reopen 04 to approve a token change           |

## 9. Mandatory second pass

After all repairs, start from the top of the canonical checklist again. Re-run
all affected static/build/measurement checks, repeat the structured layout
audit, and flip through the full deck—not only changed pages. Any open P0/P1
means the delivery Gate fails.

## QA mindset

The reviewer is a skeptical audience member in the back row. If an element has
no communicative purpose, remove it. A successful build is necessary, not
sufficient; a repair is successful only when regenerated evidence confirms it
without violating an earlier decision.
